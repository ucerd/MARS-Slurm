# Publication checklist

This is a complete repository tree, not an overlay requiring another export. It is not a Git checkout (no .git directory). The old public code and compact data were merged with the verified cluster archive and the new README and citation metadata. The original accepted data paths are retained and augmented with raw logs. The earlier collector and diagnostic variants are segregated under legacy/.

1. Resolve the SSH credential exposure in the previous repository before publishing. The old snapshot contained an SSH private-key file and its corresponding public-key file under accidental ssh-agent-related names. Neither is included here. Revoke the exposed public key from every authorized_keys file, deploy key, or other authorization where it was trusted; issue replacement credentials as needed. Remove both tracked files and purge the sensitive file from repository history using an appropriate sensitive-data removal procedure. Merely removing the files in a new commit does not revoke the key or remove older copies. Coordinate history rewriting with collaborators and GitHub support as appropriate.
2. Review the original logs and code for infrastructure details approved for publication (including host names, interface information, internal addresses, paths and account identifiers). A basic credential-pattern screening found no remaining matches, but cannot guarantee absence of sensitive information. If anything is redacted, document it and regenerate release checksums; do not silently alter scientific observations or label edited sources as byte-identical.
3. Verify in a fresh unpacked copy: `sha256sum -c SHA256SUMS` and `python3 analysis/verify_release.py`.
4. Merge this directory's contents, including .gitignore and .gitattributes, into a clone of the existing ucerd/MARS-Slurm repository. Do not delete the existing repository or overwrite its .git directory. Review git status/diff and ensure old credential files are absent from the tracked working tree. Commit the reviewed update on a branch, then merge it to main. Do not commit the ZIP archive itself.
5. Create tag v1.1.0 and a GitHub release after confirming the merged repository matches the verified files. Use docs/RELEASE_NOTES.md for the release description. Cite the actual versioned release in the manuscript after publication. No DOI or remote publication is claimed here.
